- [触发条件]中间骨骼(_M)执行拷贝翻转 -> [根因]直接暴力翻折全量 World Matrix (S_x * WS_max * S_x) 导致包含着预设角度偏移（比如基础带 -90度 Y 轴偏转）的 BasePose 也被整体颠倒至异侧，产生严重的轴向混乱 -> [正确方案]改用计算 Target 到 Base 的 Local Offset Delta 并对 Delta 执行 S_x * Delta_R * S_x 来剥离世界翻转与本地基础角度，最后组合还原。 -> [避坑规则]所有的中间部位骨架镜像严禁翻转原生 Transform 系，必须走位移/偏差特征镜面反射！
- [触发条件]未选中模型操作时多边形拷贝翻转失效 -> [根因]原先的 run_joint_or_polygon 代码绑定了对当前 Maya Object Select 列表的状态检测，没选中模型就直接跳过。 -> [正确方案]修改底层的 mirror_polygon_targets 去直接扫描 aliasAttr 定位匹配的 blendShape 节点自动建立。 -> [避坑规则]封装通用的数据读写管道时禁止强耦合 UI 层面的鼠标选中判断。
- [触发条件]使用外部节点或后台二次驱动子控制器导致新建 Pose 修形结果为空 -> [根因]提取物理形变时，系统需要在 `reset_all()` 阶段把全场归零并隔离当前的驱动器，但在非通道绑定、属性被约束锁死的环境下，场景无法顺利闭合且驱动器取回权重系数失败，导致算出 0 差异或被安全舍弃。 -> [正确方案]改版 UI 逻辑引入带有智能分辨孤立目标的 `restore_controllers` 协助预检；业务逻辑上遇到二次封装的黑盒控制，必须依靠外部“干净空控制器”截流物理坐标完成录制。 -> [避坑规则]绝对禁止尝试用 MFace 系统为一个被节点网接管死锁的“虚拟指挥员控制器”做 Add/Edit 物理录制！必须分层把发令端口和物理载体切开。
- [触发条件]移动主组后骨骼生成飘走 -> [根因]原有绑定在OPM属性中误串联了世界坐标转换产生双倍偏移 -> [正确方案]废除原世界矩阵运算，所有眼部骨骼与大控统一仅接入纯局部旋转即刻 -> [避坑规则]节点OPM属性严禁接收带有世界位置特征的复合矩阵！
- [触发条件]创建眼球视线追踪骨骼时旋转了大组MFaces -> [根因]原先的 rig_look 直接将从 FitEye_LRoll 提取出的带有父级非标准旋转系数的世界矩阵塞给了绑定根偏移 Offset 组。导致无论系统最后如何 Aim 目标点，自身主轴（如骨骼X红轴）也总是受到绑定前残留的静态偏差角干扰（导致其错开目标直指黄色副控制器）。 -> [正确方案]在 rig_look 中引入 check_aim_roll 洗掉底层杂质，强行抹除父级矩阵中的任意静态旋转量，仅依托世界视线两坐标点重建干净的本地四元数坐标系。 -> [避坑规则]直接读取不纯净的定位器世界矩阵（包含父组各种Transform扰动）来充当“方向基准”的做法隐患极大！涉及直线相连类的组件必须靠两点计算以除垢和重构矩阵。
- [触发条件]复位单体控制器时意外清空了全场Pose -> [根因]原有的 reset_all() 没有隔离设计，一旦调用就会全盘遍历 Bridge 上所有的修形目标并根据 default_value 强行重置，导致原本应该做到独立空间归零的逻辑扩大化。 -> [正确方案]为 reset_all 增加 ctrls 列表入参过滤，并在 restore_controllers 内部精准派发选中的控制器给它，从而实现针对被选中的控制器及其附属 Pose、BS 形态实施精准局部的复位隔离。 -> [避坑规则]实现局部控制器复位时必须连带过滤并清零其次级控制的形变数据，否则其绑定的底层目标权重（如超出死区的 BS Target）依然会残留在空间当中！
- [触发条件]复原控制器选中对象时触发 'Ctrl' object has no attribute 'reset' 或实例化失败 -> [根因] `Ctrl` 类的构造函数 `__init__(name)` 的入参要求是经过格式剥离的核心后缀名(如 Eye_L)，而非Maya场景大纲中的全名长路径(如 FCtrlEye_L)。但在 `restore_controllers` 中直接把 `get_selected_ctrls()` 抓取到的长路径传递给了 `Ctrl(c)` 实例化，导致解析错误或找不到对象。并且原 `Ctrl` 实例并未暴露针对个体的 `reset()` 方法。 -> [正确方案]直接对原生控制器的字符路径执行基于矩阵的底层清零操作 `rest_ctrl(c)`，完全剥离对高层封装类 `Ctrl` 的重组依赖。 -> [避坑规则]在使用 MFace 面部组件的 `Ctrl` 类进行实例化时，绝不能无脑塞入 Maya大纲的全路径名称，必须确保入参为原始 core 后缀名！对于只涉及局部坐标归零的轻量级操作，应首选模块内的防呆工具函数 `rest_ctrl()` 代替。
- [触发条件]勾选排除的驱动效果仍泄漏进delta → [根因]`reset_all`中`rest_ctrl(ctrl)`重置整个Transform，同控制器的其他属性target（如.ty/.roll/.puff）触发rest_ctrl时连带将exclude中的.tz归零 → [正确方案]构建`exclude_ctrl_set`，当控制器有任何属性在exclude中时，只用`setAttr(ctrl.attr, default)`重置单个属性，不调用rest_ctrl整体重置Transform → [避坑规则]rest_ctrl是全Transform重置，exclude必须按控制器粒度拦截，不能只按单属性跳过！
- [触发条件]驱动值为0时delta反向污染 → [根因]`edit_joint_target`中`active_drivers=False`(驱动=0)时走else分支调用`set_pose_by_targets`将驱动恢复到阈值，但快照时驱动=0 → [正确方案]始终从`driver_cache`恢复快照时的驱动值，移除active_drivers分支判断 → [避坑规则]基准状态的驱动值必须与快照时完全一致！
- [触发条件]auto_update_threshold中cmds.keyframe报Cannot move keys → [根因]目标浮点位置与已有key冲突 → [正确方案]用try/except RuntimeError包裹keyframe edit调用 → [避坑规则]SDK keyframe编辑操作必须捕获RuntimeError！
- [触发条件]编辑COMB目标关闭某组件驱动但delta仍叠加该效果 → [根因]基准计算时排除驱动保持0(非阈值)，delta不含反向补偿；COMB激活时a_indiv+delta=a_indiv未被抵消 → [正确方案]排除的COMB组件驱动在基准中恢复到SDK阈值，delta自动含-a_indiv补偿 → [避坑规则]COMB目标排除驱动必须在base恢复阈值而非保持0！
- [触发条件]COMB组件驱动处于正常阈值却出现在弹窗中 → [根因]对COMB组件驱动用default_value而非SDK阈值(old_value)过滤 → [正确方案]COMB组件驱动用own_thresholds[ca]比较，处于阈值则跳过 → [避坑规则]COMB组件弹窗过滤必须比SDK阈值而非默认值！
- [触发条件]auto_update_threshold误改排除驱动的SDK阈值 → [根因]无exclude参数，递归COMB时对所有组件更新 → [正确方案]添加exclude_ctrl_attrs参数，匹配的ctrl_attr直接return跳过 → [避坑规则]阈值更新必须传递并尊重排除集！
